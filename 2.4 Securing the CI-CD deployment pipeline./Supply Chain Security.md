## Cloud Build
___


### Automated Builds

Automated build or scripted build defines all build steps in a script, including retrieving the source code. Provides consistency, but also not just code and steps, but also environment should be consistent and trusted.

DO NOT Release local build, NOT SLSA 1 compliant.

### Build provenance

Build provenance can be generated by Cloud Build up to SLSA Level 3.

Which means it is available, authenticated, service generated, and non-falsifiable.

Generating build provenance helps you to:

- Verify that a built artifact was created from trusted source location and by a trusted build system.
- Identify code injected from an untrusted source location or build system.

Use alert if provenance doesn't match, this is a big red flag.

### Ephemeral

Temporary build env meant to last a single invocation.
Helps with
1. Clean builds
2. No residual files
3. No residual environment settings
4. Secure, as it's always being unused
5. Reduce maintenance overhead, make predictable build even with no caching etc. etc.

### Deployment Policies

Integrate CB with Binary Authorization to check for build attestation, and block deployment of non-CB images. Reduces risk of non-authorized software.
